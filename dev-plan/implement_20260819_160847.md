# implement_20260819_160847.md

작성 일시: `2026-08-19 16:08:47 KST`

이 문서는 검증된 Alpine Python 패키지 팩이 없는 깨끗한 클론에서도 TripPilot을 안전하게 빌드할 수 있도록, 패키지 팩의 별도 프로비저닝·검증·주입 경로를 고정하는 작업 문서다. 일반 빌드 중 네트워크에서 런타임을 내려받는 방식은 도입하지 않는다.

## 개발 목적

- 현재 원격 `main`에 lock/SBOM만 있고 22개 Alpine Python `.apk`가 없는 상태를 재현 가능한 개발·CI 입력 계약으로 전환한다.
- `debug`는 Fake runtime 경로를 유지한 채 깨끗한 클론에서 APK 조립·설치가 가능하게 한다.
- 실제 Alpine/Codex runtime을 포함하는 `secureDebug`와 `release`는 검증된 production 패키지 팩 없이는 계속 fail-closed한다.
- 외부 팩을 제공했을 때 Gradle, Phase 4 gate, 문서의 입력 계약을 하나로 일치시킨다.

## 개발 범위

- 기존 `python-pack.lock.json`과 `sbom.spdx.json`을 정본으로 사용하여 Alpine 공식 HTTPS URL의 22개 `aarch64` APK를 **별도 명시 명령**으로 내려받는 표준 라이브러리 Python 프로비저너를 추가한다.
- 프로비저너가 각 파일의 이름·크기·SHA-256을 lock과 대조하고, 완전한 팩만 명시한 출력 경로에 원자적으로 준비하게 한다.
- `ALPINE_PYTHON_PACKAGE_DIR`가 없을 때 debug 조립이 불완전한 in-tree metadata를 production 팩으로 오인하지 않도록 Gradle variant 계약을 정비한다.
- `secureDebug`/`release` 및 명시적 Phase 4 production gate에는 existing Python-pack verifier를 연결한다.
- Phase 4 verifier가 in-tree의 특정 APK 존재만 하드코딩하지 않고, 명시된 외부 팩을 existing verifier로 검사하게 바꾼다.
- 로컬·CI 실행 문서와 테스트 매트릭스에 팩 준비, offline build, 설치 smoke 절차를 기록한다.

## 문서 기반 제약 사항

- Python 패키지 팩은 `production: true`, SPDX 2.3 SBOM, `aarch64`, `python3` 포함, lock의 정확한 크기·SHA-256·APK metadata 조건을 모두 만족해야 한다.
- 기존 vendor verifier는 네트워크 fallback을 허용하지 않는다. 새 프로비저너만 명시 실행 시 네트워크를 사용하며, normal Gradle build는 local path만 소비한다.
- TripPilot 공개 경계에는 raw CLI·credential·custom OAuth를 추가하지 않는다.
- `debug`는 real OAuth가 꺼진 deterministic Fake runtime이고, 실제 runtime 검증 대상은 arm64 `secureDebug`/`release`다.
- 사용자 변경을 stash, reset, 삭제, 임의 commit 하지 않는다. production package bytes는 Git에 추가하지 않는다.

## Phase 2. 팩 프로비저닝 도구 구현

- [ ] Python 표준 라이브러리만으로 HTTPS 다운로드를 구현한다. SBOM mapping의 allowlisted HTTPS origin 외 URL·redirect를 거부하고 timeout/최대 바이트를 적용한다.
- [ ] 각 파일은 temporary sibling에 내려받아 lock의 filename, size, SHA-256과 대조한다. 모든 검증 후 lock/SBOM과 `packages/`를 구성하고 existing `verify-python-package-pack.py --verify-source --require-production`을 최종 호출한다.
- [ ] 이미 존재하는 output은 기본 거부하고, 명시적 replace 옵션에서만 검증된 새 결과로 원자적 교체한다. 실패·Ctrl-C·검증 오류 시 partial directory를 정리한다.

- [ ] `alpine-python-pack-bundled/build.gradle.kts`를 조정해 `ALPINE_PYTHON_PACKAGE_DIR`가 있을 때만 production source를 prepare하게 한다. 미제공 debug에서는 `available=false` status asset을 생성하되 네트워크 접근은 하지 않는다.
- [ ] `secureDebug`/`release` packaging 경로가 `verifyProductionPythonPackagePack`에 의존하도록 연결하고, 입력이 없거나 invalid하면 APK 산출 전에 원인별 메시지로 실패하게 한다.
- [ ] `scripts/verify_phase4_gate.py`에 `--python-pack-dir` 옵션과 환경 변수 fallback을 추가하고, hard-coded file existence 대신 existing verifier의 production validation을 사용한다.
- [ ] Phase 4 static source-only 모드와 production-input-required 모드를 명시적으로 구분한다. 전자는 clean clone의 source boundary를 검사하고, 후자는 valid pack이 있어야 PASS한다.
- [ ] Gradle task/Phase 4 오류 메시지에 필요한 환경 변수, expected pack layout, verifier 명령을 안내하되 URL·credential·package bytes는 로그에 노출하지 않는다.

## 잔여 리스크 / 후속 과제

- Alpine mirror에서 lock에 고정된 과거 패키지를 더 이상 제공하지 않으면, 프로비저너는 실패해야 한다. 새 package set/lock/SBOM 갱신은 별도 공급망 검토 계획으로 분리한다.
- secureDebug에는 pinned official Codex CLI asset과 arm64 device 조건도 있으므로, Python pack이 준비되어도 CLI retrieval·실기기 OAuth는 독립 gate로 유지한다.
- release signing material과 실제 OAuth는 사용자의 권한·계정이 필요한 외부 상태이며, 이 계획의 자동화 범위에 포함하지 않는다.
