# implement_20260816_201733.md

작성 일시: `2026-08-16 20:17:33 KST`

이 문서는 TripPilot의 기능·보안 경계를 변경하지 않고, 현재적인 Android 여행 기록 UX로 화면 언어와 정보 계층을 재구성하기 위한 작업 문서다.

## 개발 목적

로컬 우선 여행 관리라는 제품 목적을 유지하면서, 현재의 범용 폼·카드·7개 가로 탭 중심 화면을 **Field Route Journal**로 개선한다. 첫 화면은 다음 여정을 바로 읽게 하고, 상세 화면은 여정·준비·보관함·도움의 네 가지 사용 맥락으로 재구성한다.

## 개발 범위

- One UI의 시야/상호작용 영역, Android adaptive navigation, TripIt의 단일 itinerary 집중, Wanderlog의 여행 맥락 패턴을 검토해 TripPilot에 맞는 최소 설계 결정을 문서화한다.
- 원격 이미지 없이 로컬 번들 Field Route hero artwork 1종을 생성·매니페스트 등록·여행 목록에 적용한다.
- 디자인 방향, 토큰, 화면 맵, 에셋 정책, visual QA 기준을 새 설계와 일치시킨다.
- 여행 목록/빈 상태를 먼저 구현하고, 이후 상세·입력·외부 승인 화면을 기능 parity를 보존하며 순차 개선한다.
- 모든 화면에서 명시적 사용자 승인, 로컬 우선 저장, Codex 초안의 비자동 반영 경계를 유지한다.

## 제외 범위

- 여행 DB schema, Room migration, Codex OAuth/runtime, Calendar/지도/브라우저/파일 실행 로직 변경
- 원격 사진·지도 타일·외부 이미지 CDN·도시 사진·브랜드 로고 추가
- 새 백엔드, 계정, API key, 분석 SDK, 광고, 범용 채팅, 디자인 도구 런타임 의존성
- OpenMinis 소스·Gradle·sandbox·MCP·browser automation 이식
