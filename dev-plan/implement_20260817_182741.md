# implement_20260817_182741.md

작성 일시: `2026-08-17 18:27:41 KST`

이 문서는 `design-render-skill`의 폐쇄형 디자인 검수 원칙을 TripPilot Android 프로젝트에 맞게 적용하기 위한 범위를 고정하고, 구현이 웹 랜딩 도구 이식이나 제품 기능 변경으로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

TripPilot의 디자인 정본(`tokens.json`, 화면 맵, 디자인 방향)과 실제 Jetpack Compose 런타임 사이의 불일치를 자동으로 검출하고, 주요 사용자 여정의 시각 회귀·한글 확대·접근성 문제를 완료 전에 차단하는 **Android 전용 디자인 루프**를 구축한다.

최근 버튼 shape 토큰이 `MaterialTheme`에 연결되지 않아 기본 pill UI가 노출되었지만 기존 빌드·lint·제한된 screenshot golden만으로는 발견하지 못했다. 이번 개발은 이와 같은 디자인 QA escape를 다음 네 층으로 방지한다.

1. 버전 관리되는 디자인·화면·자산 계약
2. `tokens.json`과 Compose 런타임의 계약 검사
3. 에뮬레이터 기반 시각·레이아웃·접근성 검수
4. P1/P2 이슈가 남으면 완료를 차단하는 실행 상태 계산

## 공통 진행 규칙

- Phase는 `1 → 2 → 3 → 4 → 5` 순서로 진행하며 앞선 Phase의 자체 테스트가 끝나기 전 다음 Phase를 시작하지 않는다.
- 구현 중 발생한 이슈는 해당 Phase에 증거와 임시 조치만 먼저 기록하고, 해결·검증 후 원인을 확정한다.
- 체크박스 상태를 실제 진행 상태와 맞게 갱신한다.
- 문서에 없는 UI 재설계, 데이터 모델 변경, 외부 기능 추가를 하지 않는다.
- 기존 프로젝트 API, Compose test, Android SDK, Python/셸 표준 기능을 우선하고 Playwright 등 새 의존성을 추가하지 않는다.
- 공통화는 이번 디자인 검사 범위에서 실제 중복을 줄일 때만 수행한다.
- 자동 검수 스크립트는 대상 serial이 `emulator-*`가 아니면 테스트 시작 전에 실패해야 한다.
- 사용자 소유 실기기는 `adb install -r`, 수동 화면 확인, process 확인만 허용하며 uninstall/clear/instrumentation을 실행하지 않는다.
- 캡처 전에 light/dark, font scale, `wm size/density`, animator 설정의 기준값을 기록하고 완료·실패 시 복원한다.
- 디자인 캡처용 여행은 고정 날짜·고정 문구·로컬 fake draft를 사용하며 네트워크와 외부 승인을 실행하지 않는다.
- `P1` 또는 `P2`가 열려 있거나 필수 런타임 캡처가 없으면 디자인 루프를 완료로 표시하지 않는다.
- 기존 Golden을 구현 결과에 맞추기 위해 자동 갱신하지 않는다. 의도된 변경인지 검토 후 별도 update 단계를 수행한다.
- material impact·재발 위험·QA escape·보안/개인정보/무결성 near-miss·큰 재작업만 occurrence 후보로 기록한다.
- 개발 종료 전 모든 occurrence 후보를 `plan-only | existing-reference | new-lesson`으로 분류한다.

## 잔여 리스크 / 후속 과제

- API 제조사별 글꼴·렌더링 차이는 에뮬레이터 Golden만으로 완전히 검증할 수 없다. 실기기는 데이터 보존형 수동 smoke로만 보완한다.
- Pixel Golden은 OS/Compose/font 변화에 민감하므로 업그레이드 시 디자인 변경과 환경 변경을 분리해 승인한다.
- 실제 TalkBack 음성 순서와 switch access는 semantics test를 보완하는 별도의 수동 접근성 점검이 필요하다.
- 새 화면이 추가되면 모든 조합의 Golden을 만들지 말고 content contract에서 위험도를 평가해 core golden 또는 matrix-only로 분류한다.
