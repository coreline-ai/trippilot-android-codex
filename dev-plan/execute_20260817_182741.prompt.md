# TripPilot Android 디자인 루프 구현 프롬프트

아래 내용을 그대로 실행 지시로 사용한다.

---

TripPilot Android 앱의 **디자인 정본과 Compose 런타임을 닫힌 검수 루프로 연결**하는 작업을 아래 최종 실행 계약에 맞춰 구현하라. 제품 화면을 다시 디자인하지 말고, 토큰 불일치·시각 회귀·접근성 누락을 완료 전에 차단하는 게이트를 만든다.

## 프로젝트 기준

- 프로젝트 루트: `/Volumes/Eprojects/project_202608/trippilot-android-codex`
- 작업 지침: `AGENTS.md`
- 구현 계획: `dev-plan/implement_20260817_182741.md`
- 디자인 정본: `design/design-direction.md`, `design/screen-map.md`, `design/tokens.json`, `design/tokens.md`, `design/visual-baseline.md`
- 자산 정본: `docs/asset-manifest.md`, `.grok/skills/trippilot-design-assets/`

- 기존 캡처: `scripts/run_design_journey_capture.sh`, `scripts/run_phase5_screenshot_golden.sh`

## 최종 목표

다음 네 층이 한 명령으로 재현되고, P1/P2가 열려 있으면 완료로 표시되지 않아야 한다.

1. 버전 관리되는 화면·자산 계약
2. `tokens.json`과 Compose 런타임의 계약 검사
3. 에뮬레이터 기반 시각·레이아웃·접근성 검수
4. 실행 상태(`RUN_STATE`)로 완료를 차단하는 품질 게이트

최근 QA escape는 action shape가 토큰에만 있고 `MaterialTheme`/일부 버튼에 연결되지 않아 pill이 노출된 일이다. 이번 작업은 그 종류의 미연결을 자동 실패로 만든다.

## 시작 전 필수 작업

1. `AGENTS.md`, `dev-plan/implement_20260817_182741.md`, `design/*`, `docs/asset-manifest.md`, `docs/test-matrix.md`, `TripPilotTheme.kt`, `TripPilotComponents.kt`, `TripPilotApp.kt`, 기존 golden/journey 스크립트를 먼저 읽는다.
2. `git status --short`를 확인한다. 현재 worktree의 변경은 사용자 작업으로 간주한다.
3. 사용자 변경 파일을 삭제, stash, reset, checkout, commit하지 않는다. `paseo.json`은 만지지 않는다.
4. 병렬개발계획/`dev-plan-v2`를 사용하지 않는다. 사용자가 명시적으로 병렬개발계획을 요청하지 않은 상태다.
5. 계획을 다시 제안만 하지 말고 **Phase 1부터 실제 스킬·계약·테스트·스크립트를 만든다.**
6. `https://github.com/coreline-ai/design-render-skill`은 404일 수 있다. 원격 스킬을 기다리지 말고, 이 프롬프트와 구현 계획의 결정 표를 원칙 정본으로 사용한다.

## 이미 끝난 작업 — 다시 하지 말 것

- empty 슬롯 자산과 `trippilot-design-assets` 스킬은 이미 있다. 새 그림·hero 교체·아이콘 팩을 만들지 않는다.
- Trip Briefing GUI, Room v2, Codex adapter, Calendar/SAF 승인 UI는 제품 범위 밖이다.
- 기존 golden 4장(`01`–`04`)은 사람 승인 없이 `update`하지 않는다.

- OAuth, Codex runtime, 네트워크 권한, Calendar/지도/브라우저/파일 승인 경계 변경
- 모든 화면×테마×크기 조합의 pixel golden 폭증
- 사용자 소유 실기기에서 `connectedAndroidTest`, uninstall, clear data, Gradle instrumentation
- 전체 `connectedDebugAndroidTest`(vendored Alpine native 테스트 포함). UI 게이트는 `:app:connectedDebugAndroidTest`만 사용
- token/credential/auth.json/prompt/response/사용자 여행 원문을 logcat·보고서·backup에 기록

### 반드시 유지

- `design/tokens.json`이 값의 정본. Kotlin에 두 번째 팔레트를 만들지 않는다
- 네 목적 영역 `여정/준비/보관함/도움`, 한 화면 한 primary action
- 에셋 생성은 `.grok/skills/trippilot-design-assets/`만 소유. 루프는 존재·해시·화면 회귀만 검사
- Calendar/지도/브라우저/SAF/OAuth는 확인 UI 이후에만 실행
- golden 자동 갱신 금지. verify만 기본

## 잠근 결정 — Phase 1에서 문서에 그대로 적을 것

이 표는 구현 중 다시 묻지 않는다.

### 스킬·계약 위치

- 디자인 루프 스킬: `.grok/skills/trippilot-design-loop/` (`.agents/skills/`가 아님)
- 화면 사람 정본: `design/screen-map.md`
- 기계 계약: `design/audit/*.json`은 screen-map / tokens / asset-manifest의 **검사 가능한 부분집합**. 새 화면 ID를 JSON에만 만들지 않는다
- `asset-manifest.json`은 `docs/asset-manifest.md`와 실제 파일 경로를 읽는다. 두 번째 인벤토리를 만들지 않는다

### P1 / P2 / P3

| 등급 | 예 | 완료 |
|---|---|---|
| P1 | 토큰-런타임 불일치, 필수 golden 실패, contrast 미달, 승인 전 외부 실행, 필수 캡처 누락, 실기기 instrumentation 시도 | 차단 |
| P2 | 2.0x/dark에서 CTA·날짜 잘림, 최소 touch target 미달, sheet footer 미도달, TalkBack 순서 붕괴 | 차단 |
| P3 | 600/840 정렬, contact sheet 미세 차이, 문서 문구 | `passed-with-notes` |

### 토큰 ↔ Compose 매핑

검사 대상과 예외를 `design/audit/design-qa.config.json`에 고정한다.

| 토큰 | 런타임 | 판정 |
|---|---|---|
| `primary`/`onPrimary`/`surface`/`onSurface`/`error` 등 ColorScheme에 있는 pair | `MaterialTheme.colorScheme` | 불일치 시 P1 |
| `wayfinding` | `secondary` | 불일치 시 P1 |
| `ai` | `tertiary` | 불일치 시 P1 |
| `action` 14dp | `TripPilotActionShape` / `shapes.small` | 불일치 시 P1 |
| `surface` 20dp | `shapes.large` | 불일치 시 P1 |
| `hero` 28dp | `TripPilotHeroShape` / `shapes.extraLarge` | 불일치 시 P1 |
| typography display/title/section/body/label/utility | `TripPilotTypography` | 불일치 시 P1 |
| `boarding` / `onBoarding` | `PrimaryAction` 전용 색. ColorScheme 필드가 아님 | 컴포넌트 색 검사. ColorScheme 부재는 실패가 아님 |
| `success` dark `#7ED7AF` | 라이트 `MossGreen`만 테마에 있음 | 허용 예외로 기록 |

| `minTouchTargetDp` 48 | `PrimaryAction` 최소 높이는 52 | 48은 전역 하한, 52는 CTA 하한. 둘 다 충족해야 함 |

`TripAreaNavigation`의 비선택 `TextButton`은 기본 stadium이 될 수 있다. Phase 2 경계 테스트에 포함하고, 실패하면 action shape를 부여한다. 네비게이션을 재디자인하지 않는다.

### Golden과 Journey

- 안정 Pixel Golden: 360dp / light / 1.0x / API 28+ emulator
- 기존 4장 유지: list empty, summary, draft review, external confirmation
- 추가 2장만: `05-itinerary`, `06-readiness` (예약/출처는 Journey contact sheet)
- Journey 픽스처는 `LocalDate.now()`를 쓰지 않는다. 고정 날짜·고정 문구·fake draft
- 360dp dark/2.0x, 600dp light/1.3x, 840dp light/1.0x는 pixel golden이 아니라 semantics + contact sheet

### 시각 승인

- 스키마/템플릿만 `design/audit/design-review.json`에 versioning
- 실행 결과 `app/build/reports/qa/design-loop/RUN_STATE.json`은 Git 비추적
- 사람 승인이 없으면 `completed`가 될 수 없다. 승인 절차를 스킬에 한 단락으로 적는다

## 구현 순서와 Gate

반드시 **Phase 1 → 2 → 3 → 4 → 5** 순서로 진행한다.

- 다음 Phase는 이전 Phase의 구현·자체 테스트·계획 checkbox 갱신이 끝난 뒤에만 시작한다.
- 파일 수가 많아지면 계획대로 기존 journey/golden 스크립트에 최소 변경한다. 계약 검증 / 캡처 / 상태 집계를 한 파일에 섞지 않는다.
- 각 Phase 끝에 `implement_20260817_182741.md`의 해당 checkbox를 실제 통과 항목만 `[x]`로 바꾼다.
- 매 Phase마다 명령, 환경, PASS/FAIL, 미해결을 `docs/test-matrix.md`에 누적한다.
- 발생 이슈는 `OCC-<id> | 시각 | 증상 | 영향 | 재현/증거 | 임시조치`로만 먼저 기록한다.

## Phase 2 — 토큰-런타임 검사

### 구현

- `scripts/verify_design_contract.py`: tokens.json 키/범위/contrast
- `DesignTokenContractTest`는 Compose 런타임을 읽는다. instrumentation으로 두고 `:app:testDebugUnitTest`에 억지로 넣지 않는다. JVM이 필요하면 매핑 fixture만 unit으로 둔다
- `PrimaryAction`, 선택 navigation, form confirm, draft apply가 action 14dp와 boarding/primary를 쓰는지 검사
- chip만 pill 허용. 일반 action stadium은 실패
- 기존 `PrimaryActionAccessibilityTest`(52dp, 2.0x 한글 bounds)를 유지하고 계약에 연결
- production visibility를 넓히지 않는다
