# implement_20260816_212537.md

작성 일시: `2026-08-16 21:25:37 KST`

이 문서는 TripPilot의 현재 색상·카드 중심 화면을 실제 제품 디자인으로 재구성하고, 참조 여행 플래너의 구체적인 준비물 정보 구조를 로컬 우선 원칙에 맞춰 적용하기 위한 순차 개발 계획이다.

## 개발 목적

TripPilot을 단순한 여행 CRUD 화면이 아니라 **“출발 전부터 귀국 후까지, 지금 확인할 한 가지를 보여 주는 여행 브리핑 앱”**으로 완성한다.

현재의 `Field Route Journal`은 토큰, hero, 4개 목적 탭까지만 부분 적용되어 있다. 이번 범위에서는 다음을 실제 UI 경험으로 연결한다.

- 여행 데이터에 연결된 단계형 브리핑·일정·준비·예약 화면
- 국제/국내 기본 준비물의 세분화된 그룹, 항목별 짧은 확인 이유
- 현재 상태와 다음 행동이 드러나는 정보 계층
- 기본 Material 카드/버튼 반복과 큰 중복 헤더를 제거한 일관된 Compose GUI

## 개발 범위

- **디자인 컨셉:** `Trip Briefing` — 여행의 예쁜 사진이 아니라 출발·이동·체류·귀국의 운영 정보를 읽는 개인 브리핑 보드
- 여행 목록, 여행 상세, 일정, 준비, 예약·출처, AI 초안·외부 승인 화면의 GUI를 하나의 컴포넌트 체계로 재구성
- `여정` 영역을 사용자가 바로 이해할 수 있는 `브리핑 / 일정` 구조로 다듬고, 일자 단계 strip을 실제 여행 기간·선택 일자·완료 상태에서 계산
- 준비 항목을 서류·입국 / 결제 / 통신·전자기기 / 의류·현장 용품 / 건강·위생 그룹으로 구조화
- 기본 항목마다 `templateId`로 연결되는 짧은 안내 문구·확인 목적을 표시하고, `INTERNATIONAL`/`DOMESTIC`/`AUTO`에 맞는 로컬 기본 팩을 제공
- 기존 Room 데이터는 보존하는 migration, backup v1 호환 read 및 새 메타데이터 backup v2 계약을 설계·구현
- 참조 문서의 시간 흐름·체크리스트·예약 브리프 패턴은 자체 UI로 재구현하고, 지역·시점 의존 정보는 템플릿 기본값에 넣지 않음
- light/dark, compact/large width, 1.0x/2.0x font scale, TalkBack, keyboard/back, process recreation, 실제 Samsung 기기 visual QA

## 설계 결정

### 1. 제품 GUI 컨셉 — Trip Briefing

```text
여행 목록
  └─ 선택한 여행의 "다음 행동"과 상태를 가장 먼저 제시

여행 브리핑
  ├─ 여행 표지: 제목 · 기간 · 범위 · 다음 행동
  ├─ 단계 strip: 출발 전 → 여행 DAY 1..N → 귀국 후
  ├─ 준비 진행: 미완료 그룹 우선
  └─ 여행 서류: 다음 예약·출처 상태

일정
  └─ 선택 일자의 time rail + 종류·장소·메모·출처

준비
  └─ 그룹별 checklist + 항목의 확인 이유 + 선택 팩

보관함
  └─ 예약 문서 + 연결 출처 + 공유 예약 텍스트

도움
  └─ AI 초안 검토 / 외부 실행 승인 / 사용자가 저장한 안전 메모
```

- **고유 서명:** 기존의 장식성 `RouteRibbon`을 폐기하지 않고, 실제 여행 일자·준비·초안 검토·승인 대기 상태를 계산하는 `JourneyStageStrip`으로 바꾼다. 데이터가 없으면 상태를 꾸며 내지 않고 “일정 없음”을 보인다.
- **레이아웃:** 큰 여행 헤더는 첫 브리핑에 집중하고 다른 탭에서는 compact sticky title만 유지한다. 한 화면에 하나의 primary action을 둔다.
- **표면:** 반복 카드 stack 대신 briefing panel, group section, document row, timeline row의 네 가지 역할 있는 surface만 둔다.
- **시각 언어:** Pilot Navy=확정 정보, Cyan=현재 단계/선택, Orange=한 개의 다음 행동, Violet=아직 반영되지 않은 AI 제안, Moss=완료. 색은 label/icon을 보조할 뿐 의미의 유일한 전달 수단이 아니다.
- **자산:** 기존 field-route hero는 목록 표지에서만 재검토한다. 도시 사진·랜덤 배경을 추가하지 않으며, 새 장식이 필요하면 자체 Compose vector 또는 VectorDrawable만 사용한다.

### 2. 준비물 템플릿 데이터 경계

- `ReadinessTemplateCatalog`은 코드에 포함한 정적, 일반형 로컬 템플릿이다. 네트워크를 호출하지 않는다.
- 기본 item에는 stable `templateId`만 저장하고, 그룹명·안내 문구는 catalog가 제공한다. 수동/AI item은 `templateId == null`이며 사용자 입력 자체를 표시한다.
- Room `v1 → v2` migration은 새 `templateId` nullable column만 추가한다. 기존 기본 항목은 origin/title matching으로 display metadata를 역추론하되 원문·상태·완료 여부를 변경하지 않는다.
- 새 backup은 `v2`에서 templateId를 보존한다. `v1` 읽기와 restore는 유지하며, migration/restore는 사용자 기존 여행을 덮어쓰지 않는다.
- 국가별 비자, 전압, 환율, 날씨, 긴급 전화, 의료/법률 문구는 정적 템플릿에 넣지 않는다. 항목은 “공식 출처에서 확인”이라는 할 일과 사용자가 연결한 출처로만 남긴다.

### 3. 참조 플래너의 적용/보류 결정

| 참조 패턴 | 이번 적용 | 방법 |
|---|---|---|
| 출발 전 checklist와 항목별 이유 | 적용 | 그룹별 기본 팩, hint, 진행률, 선택 팩 |
| 일자별 브리프 | 적용 | 실제 일자 selector와 time rail, 일정 notes/출처 |
| 항공·숙소 확인 블록 | 적용 | 기존 Reservation을 브리핑/보관함에서 document row로 표시 |
| 긴급대처 구조 | 제한 적용 | user-owned 안전 메모 진입만 설계. 국가별 사실/전화번호는 자동 제공하지 않음 |
| 귀국 후 TODO | 제한 적용 | 사용자가 선택하여 추가하는 local post-trip pack |
| 경비 결산 | 보류 | 독립 데이터 계약·정산 UX 계획이 필요 |
| 사진·지도 | 미적용 | 네트워크·라이선스·자동 외부 실행을 만들지 않음 |

## 공통 진행 규칙

- Phase는 반드시 `0 → 1 → 2 → 3 → 4 → 5` 순서로 진행하며, 이전 Phase의 자체 테스트가 통과해야 다음 Phase를 시작한다.
- 기존 기능, testTag, local-first 저장, AI의 non-auto-apply, 외부 실행 승인 경계를 유지한다.
- Room schema 변경 전에 migration, backup, process recreation 테스트를 먼저 추가한다. destructive migration은 금지한다.
- UI 문구는 사용자가 제어하는 행동을 말한다. 사실이 불확실하거나 지역 의존적이면 자동 판단처럼 표시하지 않는다.
- 외부 링크·지도·Calendar·파일·OAuth는 별도 명시 확인 뒤에만 실행한다.
- 현재 worktree에는 사용자 변경이 있으므로 삭제·stash·reset·commit 하지 않는다.
- 발생 이슈는 해당 Phase에 evidence만 기록하고, 전체 구현 종료 전 `plan-only | existing-reference | new-lesson`으로 분류한다.
