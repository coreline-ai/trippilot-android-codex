# implement_20260817_213827.md

작성 일시: `2026-08-17 21:38:27 KST`

이 문서는 데이터가 있는 여행 화면이 실제로 여행 브리핑처럼 보이도록 GUI를 적용하기 위한 범위를 고정한다. 검수 도구만 추가하거나 empty illustration만 넣고 끝내지 않는다.

## 개발 목적

삼성에서 열린 `Busan Weekend`처럼 **항목이 있는 목록·브리핑·일정·준비·예약**이 Orbit/TripIt식 여행 서류 UI로 읽히게 한다. 사용자는 설치 직후 빈 화면이 아니어도 디자인 변경을 볼 수 있어야 한다.

제품의 한 가지는 유지한다. 출발 전·여행 중·귀국 후에 **지금 확인할 한 가지**를 보여 주는 로컬 브리핑이다.

## 개발 범위

- 오픈 디자인에서 **패턴만** 적용한다. 대상: Kiwi [Orbit](https://orbit.kiwi) Itinerary/Ticket/Empty 구조, TripIt식 예약 서류 카드, PackPoint식 그룹 진행
- 데이터가 있는 화면을 우선 변경한다: 목록 featured cover, 브리핑 다음 행동, `JourneyStageStrip` day rail, 일정 time rail, 예약 document card, 준비 그룹 헤더
- 기존 `tokens.json` 색·shape·type을 정본으로 유지한다. 새 팔레트를 만들지 않는다
- 기존 testTag, local-first, AI 비자동 반영, 외부 실행 승인 경계를 유지한다
- empty illustration은 새 표면 언어에 맞춰 다듬되, 이번 완료 기준이 아니다
- 변경 화면은 emulator golden/journey와 삼성 `adb install -r` 수동 QA로 확인한다

## 제외 범위

- TREK, AdventureLog, itskovacs/trip 코드·화면·에셋 이식. AGPL/GPL 모듈을 `:app`에 넣지 않는다

- Room schema, backup 포맷, Codex/OAuth, Calendar/지도/브라우저/SAF 승인 완화
- 경비 결산, 공동 편집, 온보딩/Settings 신규 화면
- 사용자 소유 실기기에서 Gradle `connectedAndroidTest`, uninstall, clear

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 구현 중 발생한 이슈는 해당 Phase에서 수정하고 기록한다.
- 체크박스 상태를 실제 진행 상태와 맞게 업데이트한다.
- 문서에 없는 범위 확장은 하지 않는다.
- 한 기능은 유지보수 가능한 최소 책임 단위로 나누고, 각 단위의 역할과 경계를 계획에 적는다.
- 계획 밖 옵션/확장/부가 기능을 만들기 위한 분리는 하지 않는다.
- 공통화는 이번 GUI 범위의 중복을 줄일 때만 수행한다.
- 기존 Compose/Room/테스트 API를 우선한다. 새 UI 라이브러리를 추가하지 않는다.
- 사용자 실기기는 `adb install -r`만 허용한다.
- golden은 사람 승인 없이 `update`하지 않는다. 시각이 바뀌면 별도 update 단계를 적는다.
